# 剧场三轴关系历史

真实世界现使用独立当前状态和结构化账本，详见 [`real-relationship-network.md`](./real-relationship-network.md)。本页的原文面板读取、出演范围限制和历史快照签名继续适用于虚构剧场；真实世界仅在首次迁移/旧备份恢复时复用中央历史读取。

## 世界归属

同一用户空间中，`writesToCharacterMemory=true` 的剧场使用 `real`，所有真实陪伴场景共享关系历史。虚构剧场使用 `theater:${entry.id}`，新剧场从独立关系历史开始。开启角色记忆输入、共通文件夹、转化记忆或改变出演名单都不改变关系世界。

中央剧情和虚构关系面板继续保存在 IndexedDB `messages`，`story_theaters` 提供所属模式。真实网当前状态、账本及独立布局复用 `assets`，首次迁移不改写旧楼层。不新增表、索引或数据库版本。新回复在 `metadata.theaterRelationshipScope` 固定归属；旧回复未带作用域时，仅根据可核对的所属剧场推导。缺少所属条目、来源或线程不匹配、作用域与所属剧场冲突的记录不加入关系历史。角色镜像、总结和向量召回不作为分数来源。

## 人物对与记录协议

关系键是有方向的角色 ID 对，如 `[狛治ID, 香奈乎ID]`。任意人物对均可独立更新，不再要求包含 `primaryCharacterId`；旧字段保留备份兼容。姓名仅用于显示，重名角色不合并。虚构出演模式要求双方在实际 `theaterCastIds` 内；真实关系独立解析，以请求候选 ID 和关系证据校验。自由续写依据正文出场和关系事实填写。直接互动分组是交流记录，不充当关系分数的硬门槛，因为单向注意、信任和扰动也可能形成关系事件。

模型按人物对分别评估两个方向：首次 FL 使用角色卡、既有关系、共同经历给出 `score`；后续使用 `delta`。每轴更新需要 `trigger` 和 `evidence`，已有分数忽略模型误填的绝对值，最终限制在 0–100。未提供另一方向的事实时保留其历史，不复制另一方分数。FL 无首次依据时保持未初始化，下一次有依据时再评估。

真实剧场的出演名单缺失或无效不影响已经有效识别的关系变化；关系报告失败保留原状态。虚构剧场仍沿用原来的出演范围限制，人工纠正名单不补造评分。

RI 保留恋爱性吸引的判断与证据要求；DI 保留 active/ended、mild/moderate/strong 和原有回落公式。回落只针对本轮有关系事实并被记录的方向；省略的人物对、其他人的回合和场外对话不使历史 DI 自动变化。

生成后仍使用 `<affinity_panel mode="three_axes">` / `<affinity_person>` 展示面板，新增可选字段：

- `<history_version>2</history_version>`：新事件协议。
- 轴内 `<initial>true/false</initial>`：首次评分或后续变化。
- 轴内 `<event_delta>`：有证据的原始变化量，保留封顶/触底之前的增量；`delta` 仍显示当轮实际变化。DI 的 `phase` 保留事件阶段，重放时从当前基线重新计算 ended 回落。
- `<self_record>` 内的 `character_id`、`character_name`、`state_note`：按人物保存新的自我记录，不再依附中心角色。

以上字段由程序规范化，不要求模型填写事件版本或计算回落。重复面板、重复方向、非法 ID 和损坏协议不写入分数，正文保留。程序校验结构、ID、出演范围和证据字段；证据是否确实发生、是否属于恋爱性心动仍由模型按正文判断。

## 顺序、重写、编辑与删除

历史按中央消息主键 ID 重放，表示保存提交顺序。现实设备时钟变化、正文时间跳跃、角色剧情时间和镜像时间均不改变关系顺序。重写沿用原消息 ID，只读取该 ID 之前的同世界历史，排除旧版本和后来其他剧场的事件。

新 v2 历史按首次评分与有证据的增量重放。改写早轮后，后续新协议增量基于改后的初值重新计算；后轮已显示的面板保留其生成时快照，下一轮读取的基线使用重放结果。修改/删除旧正文不会重新请求模型解释后续剧情。编辑关系数值时，初评修改 `score`，后续变化修改 `event_delta` 及证据；只修改后续面板的显示 `score` 不会改写关系事件。

删除初始评分且没有更早可用基线时，后续增量不凭自己的显示快照恢复被删除的分数，该轴等待重新初评。删除一层只移除该层记录；保留的其他楼层与已有长期记忆按原产品规则处理。删除整个剧场移除该来源的关系事件。真实网的手动修正独立保留；修改出演名单不撤销已有效识别的真实关系。虚构剧场修改出演名单后，读取时排除不再实际出演的关系双方。

旧 XML/JSON 三轴作为绝对快照读取，同一方向同一轴取最后提交的有效值，**不将两个旧剧场的绝对分数相加**。五维保持原文回看，只续接能明确对应 ID 的自我记录，不换算 FL/RI/DI；仅有 `active_char` 姓名的旧自我记录保留回看，不猜测角色 ID。旧绝对快照无法可靠反推事件增量，因此删除/改写它之前的历史不会改写它已保存的绝对值；新回复开始使用 v2。

## 归档、备份与上下文

归档标记不删除原文，关系读取包括已归档中央楼层。手动重新总结事件盒不改变关系历史。完整备份/恢复沿用原来的条目、消息 ID 和 metadata 流程，真实网还携带当前状态、手动账本与独立布局；纯文字和纯媒体恢复范围见真实网文档。

上下文中的角色既有原文和共通文件夹内容剥离关系分数面板；剧情事实继续按原有可见范围读取。它们可提供关系事实，但分数基线只来自当前世界的关系读取器。预设只精确升级未被改写的旧默认三轴文本；用户自定义文本、开关、名称和排序保留。

## 并发提交

真实世界改为在原写事务中核对持久化图 revision；以下历史快照签名机制用于虚构世界和旧调用兼容。

生成前在同一只读事务中读取所属剧场和同世界关系楼层，保存关系内容、作用域和出演名单的快照签名。只扫描同世界中央线程，使用现有索引游标，仅保留含关系面板的楼层。

中央回复及镜像保存、出演模式重写和自由续写重写，都在写事务内重新核对这份签名。其他窗口新增、编辑、删除关系楼层，或修改其实际出演名单时，旧请求整笔回滚，保留推进/原回复，并提示重试以使用最新历史。两个真实场景同时基于同一旧关系生成时只允许先提交的一笔成功。另一虚构世界的更新以及单纯归档、摘要或时间戳变化不使关系基线冲突。

这采用保守的同世界冲突检测：即使另一窗口更新不同人物对，也可能要求重试。它避免给旧基线自动拼接新状态，不增加锁表或后台状态。
