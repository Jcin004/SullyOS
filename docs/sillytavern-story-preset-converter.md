# 酒馆预设转剧情预设

## 需求基线

| 层 | 职责 |
| --- | --- |
| 代码转换层 | 读取酒馆 JSON，解析实际顺序和分组，映射运行时槽位和采样参数，保留源文本并返回可预览的原生预设及兼容报告。 |
| 预设输入层 | 提供源条目、发送角色、启停、位置、协议选择和冲突预览。用户确认后可导出 JSON／报告，或另存到剧情预设库。 |
| SullyOS 运行时 | 继续提供角色与记忆上下文、世界书、事件盒、剧场历史、出演、私轴、经历时间和三轴。新预设调用同一套解析、渲染、记忆和记账流程。 |

### 验收约定

- 普通条目保留原文和消息角色。优先采用所选角色的 `prompt_order`，没有顺序表时采用定义数组。缺失、未引用、重复或条件不兼容的条目有明确记录。历史深度和相对顺序分别处理。
- 每组按实际顺序落在原生编辑器的一个或多个连续区间。酒馆组插件元数据与生效顺序表不一致时，报告差异。
- 角色描述和个性由现有角色上下文合并提供。世界书前置、后置、用户身份、剧情和历史使用运行时槽位。缺少关键上下文时补入可见的运行时连接位。
- 初次转换默认携带经历时间、出演、私轴和三轴协议，用户可以选择。场景条、幕后与余波、世界线、小剧场按需添加。协议用固定 ID 与标签连到已有处理。源文学提示词不被改写。
- 静态检查协议、宏、分组、正则和扩展。兼容报告逐项记录可用、近似、需运行时适配的项目。用户提供的脚本、HTML 模板和正则均作为数据处理。
- 换预设沿用剧场和角色 ID。经历时间、角色镜像、出演记录、私轴和三轴的原有记录由已有存储读取。

### 实施步骤

1. 核对目标分支、酒馆 Prompt Manager、两种输入结构与原生导入器。确定字段、槽位、深度和报告规则。
2. 新增转换器与可选协议库。给原生预设添加显式顺序和深度，继续走现有请求、展示和持久化路径。
3. 接入本地文件预览、角色顺序选择、协议选项、原生 JSON／报告导出和预设库导入。
4. 用「众生相 Gemini-v4.3」和另一种结构验证原文、分组、启停、请求顺序、采样参数、导入往返和输出边界。运行剧场存档、时间、出演、私轴和三轴回归。

酒馆依据：[Prompt Manager](https://docs.sillytavern.app/usage/prompts/prompt-manager/)、[请求编排源码](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/openai.js)、[Regex](https://docs.sillytavern.app/extensions/regex/)。

## 使用方式

打开「见面 → 剧场 → 糯米机预设制作器 → 转换酒馆预设」。选择 Chat Completion 预设 JSON，检查源条目和示例消息顺序。文件若包含多个角色顺序，可在预览里切换。默认选酒馆全局顺序 100001。导出的剧情 JSON 可走原生上传入口，兼容报告可单独保存，也可以直接将转换结果存入预设库。在原剧场的设置中切换预设会继续用同一个剧场存档。

### 当前支持范围

- 实际顺序、消息角色、条目开关、源文本、连续分组，以及 `user`、`char`、`group`、`charIfNotGroup`、`lastUserMessage` 宏。酒馆的单当前角色概念在多演员剧场使用当前请求的角色名单。
- 支持相对位置和 Prompt Manager 历史深度，深度 0 在本轮用户输入之后。指定优先级和角色一致的同深度条目合并为一条消息。在剧场开启「最后一条保持用户消息」时，历史后置规则会提前。
- 温度、Top P、频率惩罚、存在惩罚、最大输出按原生范围保存。Top K、上下文预算、Seed 等由报告列出。助手预填沿用剧情和自由续写的现有行为。
- 剧场只注入一次同类原生槽位。角色描述和个性合并进角色资料与记忆，示例对话缺少运行时来源。角色资料、执笔身份、剧情和历史必须可接入，缺失时补独立槽位，并保留源槽位开关。
- 协议库可单独选择。默认接入经历时间、出演、私轴和三轴。关闭出演协议时，如剧场仍开着出演模式，需由启用的源条目提供正确的出演报告。关闭三轴协议时，本预设暂停新三轴结算。已存的楼层、镜像、私轴和三轴历史仍按剧场与角色查找。
- 支持把内容等价的显示规则交给已有渲染，例如单独解包原生 `<story_text>` 正文。正则的实际查找和替换内容以及扩展脚本不进入原生预设。HTML、CSS、交互模板、提示词阶段剪裁、第三方变量和扩展注入依赖单独实现。
- 原生预设使用 `promptLayout: "ordered"` 及可选的 `prompts[].inChat` 记录上述编排，旧预设沿用原编译路径。

### 首个样本

「【众生相】Gemini-v4.3」的 311 条源提示词、87 个启用状态、15 个 Toolkit 分组及五项采样参数通过导入往返。两条深度 1 的复述规则保留原位置信息和各自开关。另一套范围分组中的端点有缺失，已按条目报告。92 条源正则中启用 16 条。状态栏、摘要与待办美化、剧情走向、电影片尾和群聊卡片需要各自的原生渲染约定。输入加标签、移除思维链、摘要层数限制、过滤剧场／片尾／群聊及自检文本属于运行时处理。旧版顶层提示词结构同时通过测试。

定向回归覆盖真实和虚构剧场在一次续写后切换预设，再继续生成。复用历史消息、事件盒、角色镜像的经历日期、上轮私轴和三轴基线。测试使用模拟模型响应。
